## Data / Integration Decisions

| Decision              | Choice                                                                                                                                                                                                                                                              | Rationale                                                                                                                                                                                                                                                                                                                                                                                              | Date       |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------- |
| Cover image sources   | Google Books (primary) → OpenLibrary by cover ID (fallback)                                                                                                                                                                                                         | Google Books is already the search provider; OpenLibrary ISBN endpoint silently returns a 43-byte GIF for missing covers — must check file size and fall back to cover ID lookup via search API — see `docs/runbooks/cover-image-sourcing.md`                                                                                                                                                          | 2026-06-08 |
| Demo shelf covers     | Bundled as static assets in `apps/web/public/demo-covers/`                                                                                                                                                                                                          | External CDN URLs (OpenLibrary) are intermittently unavailable; landing page demo must always render correctly for new users                                                                                                                                                                                                                                                                           | 2026-06-08 |
| API token audiences   | API trusts **both** the SPA client and the MCP client (`audience: [COGNITO_CLIENT_ID, COGNITO_MCP_CLIENT_ID]` in `apps/api/src/middleware/auth.ts`)                                                                                                                 | The MCP server proxies the user's ID token to the API, but the two use separate Cognito app clients (kept separate for independent revocation). A single-audience check rejected mcp-audience tokens with 401, breaking the MCP→API hop in dev **and** prod. `ApiStack` now receives `mcpClientId` and sets `COGNITO_MCP_CLIENT_ID`. Requires an API redeploy to apply in prod.                        | 2026-06-12 |
| Client analytics      | Authenticated `POST /v1/events` route emits CloudWatch EMF via `console.log` (no new dep, no `PutMetricData`); event `name` allowlisted; client `track()` is fire-and-forget                                                                                        | App's first event sink; lowest cost vs CloudWatch RUM / third-party; reuses Lambda + `authMiddleware`; no PII/user id in metrics — see `docs/adrs/016-client-analytics-events-endpoint.md`                                                                                                                                                                                                             | 2026-06-15 |
| ISBN canonicalization | Canonicalize every ISBN to **ISBN-13** at the API write boundary — `normalizeIsbn` (`apps/api/src/lib/isbn.ts`) now converts valid ISBN-10 → ISBN-13 (`isbn10to13`), so all entry paths (`parseIsbnParam` in `shelf.ts`, `/isbn/:isbn` in `books.ts`) store one key | A book added via search (provider ISBN-10) vs. scan (ISBN-13) previously forked into two keys, breaking duplicate detection and splitting the shared `BOOK#${isbn}` metadata cache. PR #67 fixed only the web scanner/manual path; the API is the real boundary. One-off backfill via `apps/api/scripts/migrate-isbn10-to-13.ts` (`docs/runbooks/isbn13-migration.md`) re-keys existing ISBN-10 items. | 2026-06-15 |

## UI / Design System Decisions

| Decision           | Choice                                                                                                                                                                                                                            | Rationale                                                                                                                                                                                    | Date       |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------- |
| Button primitive   | `src/components/ui/Button.tsx` with `variant`/`size`/`loading` props                                                                                                                                                              | Single source of truth for all button styles; prevents silent style drift across pages                                                                                                       | 2026-06-02 |
| Button color       | Single monochromatic style: `app`/`primary` → `slate-900`/white inverted                                                                                                                                                          | Blue `primary` variant removed — auth+app now share one neutral palette; see `docs/design-system.md`                                                                                         | 2026-06-06 |
| Neutral palette    | `slate-*` exclusively throughout — no `gray-*` or `zinc-*`                                                                                                                                                                        | Mixing near-identical neutral scales causes subtle visual noise; `slate` matches the existing dark-mode choices                                                                              | 2026-06-06 |
| Focus rings        | `focus:ring-2 focus:ring-slate-900 dark:focus:ring-slate-300` on all inputs                                                                                                                                                       | Replaces `blue-500` focus ring — monochromatic, high contrast in both modes, consistent with button system                                                                                   | 2026-06-06 |
| Auth inline links  | `underline underline-offset-2 text-slate-900 dark:text-white hover:no-underline`                                                                                                                                                  | Underline makes links identifiable without relying on color alone (WCAG 1.4.1); slate replaces blue-600                                                                                      | 2026-06-06 |
| Dynamic aria-live  | `role="status" aria-live="polite" aria-atomic="true"` wraps search/error regions                                                                                                                                                  | Screen readers must announce loading, error, and result-count changes without requiring focus move                                                                                           | 2026-06-06 |
| Shared form styles | `src/lib/form-styles.ts` exports `inputClass` / `labelClass`                                                                                                                                                                      | All auth inputs share one definition; eliminates copy-paste drift across 5 auth pages                                                                                                        | 2026-06-02 |
| Muted text floor   | `text-slate-500 dark:text-slate-400` minimum for visible text                                                                                                                                                                     | Ensures WCAG AA contrast on both light and dark backgrounds; placeholder text (exempt) may use `slate-400`                                                                                   | 2026-06-06 |
| Shelf card actions | Always visible (no hover-only reveal)                                                                                                                                                                                             | `opacity-0 group-hover:opacity-100` is invisible on touch devices                                                                                                                            | 2026-06-02 |
| Loading spinners   | `role="status"` + `aria-label="Loading"` required on all `animate-spin` elements                                                                                                                                                  | Screen readers need to announce loading state                                                                                                                                                | 2026-06-02 |
| PasswordChecklist  | Unmet rules use `○` prefix; met rules use `✓`                                                                                                                                                                                     | Shape must distinguish state, not color alone — color-blind users cannot distinguish gray `·` from green `✓`                                                                                 | 2026-06-02 |
| Scanner surface    | `ScanModal` is always-dark (camera-UI convention), wrapping content in a `.dark` context so design-system `Button`/`inputClass` render correctly; `SegmentedControl` marks the selected option with a check icon, not color alone | Camera viewfinders need max contrast regardless of app theme; the `.dark` wrapper avoids inlining button/colour classes; shape (not color) distinguishes toggle state for color-blind users  | 2026-06-13 |
| Callout primitive  | `src/components/ui/Callout.tsx` — reusable informational box (icon + title + body + optional dismiss/actions), slate palette + `dark:` variants, `role="note"`; not for form validation (use inline red/green)                    | First "do X over there" messaging primitive; powers `MobileScanHint` (points desktop users to mobile scanning) — see `docs/design-system.md` and `docs/specs/mobile-scan-discoverability.md` | 2026-06-15 |

## Glossary

| Term  | Meaning                                                                  |
| ----- | ------------------------------------------------------------------------ |
| ISBN  | International Standard Book Number (13-digit modern, 10-digit legacy)    |
| ASIN  | Amazon Standard Identification Number (for books: often matches ISBN-10) |
| Owned | A book the user physically possesses                                     |
| Want  | A book on the user's wishlist                                            |
