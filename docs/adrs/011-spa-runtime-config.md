# ADR-011: SPA Runtime Config via Deploy-Time `config.json`

**Status**: Accepted
**Date**: 2026-06-06

## Context

The SPA needs three environment-specific values at runtime: the Cognito
`userPoolId` and `userPoolClientId` (generated by `AuthStack` at deploy time) and
the API base URL (`/api` same-origin, or the execute-api URL for dev).

Originally these were injected at **build time** as Vite `VITE_*` env vars. That
forced an awkward dance: deploy `BookshelfAuth`/`BookshelfApi`, resolve their
CloudFormation outputs, set `VITE_*` env vars, *then* build the web bundle — in CI
and, painfully, by hand for local deploys (setting `$env:VITE_*` on the machine).

The constraint that makes "just pass the stacks' readonly properties into the
build" impossible: Vite bakes `VITE_*` at build time, but the Cognito IDs are **CDK
tokens** unknown until deploy. A local build cannot receive a value that doesn't
exist yet.

## Decision

Move SPA configuration from build-time env vars to a **deploy-time runtime
config**:

- `WebStack` writes `/config.json` to the SPA's S3 prefix via
  `s3deploy.Source.jsonData("config.json", {...})`, populated from the Auth/API
  stacks' **public readonly properties** (`auth.userPoolId`,
  `auth.userPoolClientId`, `api.apiUrl`). `Source.jsonData` resolves the CDK tokens
  at deploy time.
- The SPA fetches `/config.json` at boot (`lib/runtime-config.ts`) **before**
  `Amplify.configure` and before any API call. The api-client reads
  `getRuntimeConfig().apiBaseUrl`.
- Local `vite dev` (no `/config.json`) falls back to `VITE_*` env vars from
  `apps/web/.env.local`, so the local workflow is unchanged. Auth always targets
  the real Cognito pool — this is configuration, not a mock.

`config.json` shape:

```json
{ "cognito": { "userPoolId": "...", "userPoolClientId": "...", "region": "us-west-2" },
  "apiBaseUrl": "/api" }
```

## Consequences

- **`pnpm build` takes zero env vars.** Local deploys no longer set `$env:VITE_*`;
  CI drops the "resolve outputs → set `VITE_*` → build" coupling (the web bundle can
  even be built before the stacks deploy). The stack wiring carries the values, as
  desired.
- **One artifact, any environment.** The same bundle runs in dev / prod-interim /
  prod; only the deployed `config.json` differs. This also makes the
  interim→custom-domain flip (ADR-010) require no rebuild.
- The SPA does one extra `fetch('/config.json')` at boot (same-origin, CDN-cached,
  negligible). App init is already async (`main.tsx` uses top-level await).
- `config.json` is **public** — it only contains non-secret identifiers (Cognito
  pool/client IDs are public client config), same as when they were baked into the
  bundle. No secret exposure.
- `VITE_*` vars remain documented in `.env.example` for local dev (the fallback).
